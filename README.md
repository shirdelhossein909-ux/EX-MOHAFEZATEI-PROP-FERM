# PropGuard — پراپ‌گارد

> **نمی‌ذاره پراپت رو فیل کنی**
>
> سودآورت نمی‌کنه. فقط نمی‌ذاره حسابت با نقض قانون از دست بره.

یک اکسپرت متاتریدر ۵ که قوانین پراپ‌فرم را روی حساب اعمال می‌کند: ضرر روزانه، دراوداون کلی، حجم، اخبار، آخر هفته — و مهم‌تر از همه، **بدترین حالت**: اگر همین الان تمام استاپ‌های باز بخورند، حساب کجا می‌ایستد.

---

## چرا «بدترین حالت» مهم است

بیشتر ابزارهای مشابه وقتی واکنش نشان می‌دهند که ضرر **اتفاق افتاده باشد**. تا آن لحظه معمولاً دیر است.

پراپ‌گارد قبل از آن حساب می‌کند: مجموع ضرر تمام پوزیشن‌های باز روی استاپ خودشان، به‌علاوه‌ی اردرهای پندینگی که ممکن است فعال شوند، به‌علاوه‌ی کمیسیون، سواپ، اسلیپیج و **بافر گپ** (چون استاپ‌لاس تضمین قیمت نیست — گپ آخر هفته و اسپایک خبری از آن رد می‌شوند).

اگر آن عدد از کف مجاز پایین‌تر باشد، پوزیشن‌ها را قبل از رسیدن به استاپ می‌بندد.

## وضعیت فعلی

| بخش | وضعیت |
|---|---|
| موتور قوانین، محاسبه‌ی ریسک، ساعت و مرزها | ✅ نوشته شده و **۱۳۵ سناریو تست پاس** |
| قفل هفتگی، امضا، ضدتقلب | ✅ نوشته شده و تست شده |
| لاگ زنجیره‌ای | ✅ نوشته شده و تست شده |
| لایه‌ی متاتریدر (خواندن حساب، بستن، پنل) | ✅ نوشته شده، **کامپایل نشده** — روی لینوکس MetaEditor وجود ندارد |
| **قوانین ۵ پراپ** | ⚠️ **جای‌خالی — باید پر شود** |

### قوانین پراپ‌ها هنوز واقعی نیستند

تمام اعداد داخل `MQL5/Include/PropGuard/Firms/PG_Firms.mqh` **موقتی** هستند و `verified_on = 0` دارند. تا وقتی این عدد صفر است:

- پنل یک نوار قرمز «قوانین تأیید نشده» نشان می‌دهد،
- و هر خط لاگ با `"rules_verified": false` مهر می‌خورد.

راهنمای پر کردن: [`docs/FIRM_RULES_TEMPLATE.md`](docs/FIRM_RULES_TEMPLATE.md)

## نصب

۱. پوشه‌ی `MQL5/` این مخزن را روی پوشه‌ی داده‌ی متاتریدر کپی کنید
   (در متاتریدر: `File → Open Data Folder`):

```
<MT5 Data Folder>/MQL5/Experts/PropGuard/PropGuard.mq5
<MT5 Data Folder>/MQL5/Include/PropGuard/...
```

۲. در MetaEditor فایل `PropGuard.mq5` را باز کنید و **F7** بزنید.

۳. اکسپرت را روی **یک** چارت بیندازید. روی هر حساب فقط یک نسخه اجرا می‌شود؛ نسخه‌های بعدی خودشان را فقط-نمایش می‌کنند.

۴. در تنظیمات، `InpFirmIndex` و `InpProgramIndex` را مطابق تب «قوانین پراپ» انتخاب کنید.

> ⚠️ **اول با حساب دمو و در حالت «فقط هشدار» (`PG_ENFORCE_MONITOR`) اجرا کنید.** یک هفته لاگ بگیرید و ببینید ربات چه کارهایی *می‌کرد*. این هم امن‌ترین راه شروع است، هم بهترین ابزار فروش.

## معماری

```
Core/     ← خالص. هیچ فراخوانی به API متاتریدر ندارد.
          ← به همین دلیل با g++ کامپایل و اجرا می‌شود و ۱۳۵ سناریو رویش تست دارد.
Firms/    ← تنها فایلی که برای اضافه/تغییر پراپ ویرایش می‌شود.
Broker/   ← تنها لایه‌ای که با متاتریدر حرف می‌زند.
UI/       ← تم‌ها، زبان‌ها، پنل.
```

این جداسازی یک قانون سفت‌وسخت دارد: **اگر یک فایل داخل `Core/` به تابع متاتریدر نیاز پیدا کرد، تابع باید به `Broker/` برود و نتیجه‌اش به‌صورت داده به `Core` پاس داده شود.** هارنس تست دقیقاً همین را تضمین می‌کند — اگر `Core` وابستگی پیدا کند، کامپایل تست می‌شکند.

### سه لایه‌ی دفاعی

| لایه | چه چیزی را می‌گیرد | تأخیر |
|---|---|---|
| اردر پندینگ | قبل از فعال شدن حذف/اصلاح می‌شود | **پیشگیری واقعی** |
| `OnTradeTransaction` | معامله‌ی دستی یا EA دیگر، بعد از اجرا | ~۵۰–۳۰۰ms |
| تایمر ۲۵۰ms | بدترین حالت تجمعی، ضرر روزانه، دراوداون | مداوم |

**صادقانه:** متاتریدر هیچ hook قبل از اجرای اردر مارکت ندارد. معامله‌ی دستی را نمی‌شود *جلوگیری* کرد، فقط می‌شود در چند صدم ثانیه *برگرداند*. برای قانونی که این محصول رویش تمرکز دارد کافی است — چون نقض در لحظه‌ی استاپ خوردن رخ می‌دهد نه در لحظه‌ی باز شدن — ولی هزینه‌ی اسپرد دارد و لاگ آن را می‌نویسد.

## قفل هفتگی

۱. سخت‌تر کردن **همیشه** آزاد است.
۲. شل کردن تا پایان پنجره‌ی هفتگی رد می‌شود — از جمله برگرداندن سخت‌گیری قبلی.
۳. پنجره تا رول‌اوور هفتگی بروکر باز می‌ماند. بعد از آن تنظیمات آزاد می‌شود. این یک **تعهد هفتگی** است، نه حبس ابد.
۴. راه خروج اضطراری هست ولی ۲۴ ساعت طول می‌کشد.
۵. عوض شدن حساب همه‌چیز را ریست می‌کند.

و آنچه دور زدن را بی‌فایده می‌کند:

۶. اگر فایل وضعیت پاک، خراب یا دستکاری شود، پراپ‌گارد به پیش‌فرض برنمی‌گردد — **سخت‌گیرانه‌ترین تنظیماتی که تا حالا برای این حساب ثبت شده** را بازمی‌گرداند و پنجره‌ی قفل تازه‌ای می‌بندد.

> این ضدِ **تشخیص** است، نه ضدِ **نفوذ**. کلید داخل خود اکسپرت است و کامپیوتر مال تریدر است. چیزی که واقعاً کار می‌کند بند ۶ است: دستکاری را بی‌فایده می‌کند، نه صرفاً سخت.

## تست

```bash
./tests/run_tests.sh
```

هسته با `g++` کامپایل می‌شود — **همان فایل‌های `.mqh` واقعی**، نه یک نسخه‌ی جداگانه. ۱۳۵ سناریو:

| گروه | چه چیزی را ثابت می‌کند |
|---|---|
| `CLOCK` | مرز روز در تایم‌زون‌های مختلف، DST اروپا، مرز هفته، کات‌آف آخر هفته |
| `RISK` | ضرر روی استاپ، بافر گپ، کمیسیون، پندینگ، ماشین‌حساب لات |
| `DAILY` | چهار نوع مبنای محاسبه، چهار سطح تیر |
| `MAXDD` | هر چهار الگوریتم دراوداون |
| `WORST` | تشخیص نقض پیش‌بینی‌شده، حالت مانیتور، هدروم |
| `RULES` | استاپ اجباری، سقف حجم، هجینگ، اخبار، آخر هفته، ثبات |
| `GATE` | دروازه‌ی پیش از معامله |
| `WINDOW` | قفل هفتگی، باز کردن ۲۴ ساعته، بازیابی ضدتقلب |
| `LOG` | زنجیره‌ی هش، تشخیص ویرایش |

فایل‌های وابسته به متاتریدر با `tests/lint_mql5.py` بررسی می‌شوند (توازن براکت، گارد هدر، سازه‌های غیرمجاز MQL5، درستی `#include`ها).

## آنچه این ابزار **نمی‌تواند** جلویش را بگیرد

- گپ آخر هفته و گپ خبری که از استاپ رد می‌شوند (بافر گپ کمش می‌کند، صفرش نمی‌کند)
- قطعی اینترنت، بسته بودن ترمینال، اختلال بروکر
- بسته شدن بازار در لحظه‌ای که باید پوزیشن بسته شود
- قوانینی که از ترمینال قابل اندازه‌گیری نیستند (کپی‌تریدینگ، مالکیت چند حساب)

اینها در پنل و لاگ صریح نوشته می‌شوند. ادعای «غیرممکن کردن مطلق نقض» درست نیست و این محصول آن را نمی‌کند.
