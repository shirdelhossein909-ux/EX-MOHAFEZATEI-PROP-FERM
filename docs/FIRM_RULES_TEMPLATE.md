# برگه‌ی تأیید قوانین پراپ

این برگه را برای **هر پراپ** یک بار پر کن. بعد اعداد را در `MQL5/Include/PropGuard/Firms/PG_Firms.mqh` بگذار و `verified_on` را ست کن.

> **مهم:** اعداد را از **صفحه‌ی رسمی قوانین خود پراپ** بردار، نه از سایت‌های مقایسه و نه از تلگرام. پراپ‌ها قوانینشان را بدون اطلاع عوض می‌کنند و عدد اشتباه یعنی حساب سوخته‌ی مشتری تو.

## ۱. ساعت ریست روزانه ⚠️ **حساس‌ترین بخش**

| سؤال | جواب | فیلد |
|---|---|---|
| ساعت ریست روزانه چند است؟ | `__:__` | `reset_hour` / `reset_minute` |
| به وقت کدام منطقه؟ (CET؟ UTC؟ تهران؟) | | — |
| اختلاف آن منطقه با UTC چند دقیقه است؟ | | `firm_utc_offset_min` |
| آن منطقه ساعت تابستانی دارد؟ | بله / خیر | `firm_uses_dst` |

**راهنمای مقدار `firm_utc_offset_min`:**

| منطقه | مقدار | `firm_uses_dst` |
|---|---|---|
| UTC / GMT | `0` | `false` |
| CET (پراگ، وین، لندن+۱) | `60` | `true` |
| تهران | `210` | `false` |
| EST نیویورک | `-300` | `true` |
| دبی | `240` | `false` |

> اگر این را اشتباه بگذاری، تریدر فکر می‌کند روز ریست شده در حالی که نشده، به معامله ادامه می‌دهد و حسابش می‌سوزد. **این تنها فیلدی است که اشتباهش مستقیماً حساب را از بین می‌برد.**

## ۸. تأیید نهایی

بعد از پر کردن همه‌ی موارد بالا، در بلوک آن پراپ داخل `PG_Firms.mqh`:

```cpp
r.verified_on = PG_Date(2026,8,6);     // تاریخی که خودت چک کردی
r.verified_by = "hossein";             // اسم خودت
```

از این لحظه:
- نوار قرمز «قوانین تأیید نشده» از پنل برداشته می‌شود،
- تب «قوانین پراپ» تاریخ بازبینی را نشان می‌دهد،
- و لاگ‌ها با `"rules_verified": true` مهر می‌خورند.

**پیشنهاد:** هر سه ماه یک بار دوباره چک کن. پراپ‌ها قوانین را عوض می‌کنند و تاریخ بازبینی روی پنل، خودش یک ویژگی فروش است — رقبا این را ندارند.
